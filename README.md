# GLaDOS TTS для Home Assistant

Русский голос **GLaDOS** для Home Assistant: Wyoming-сервер на основе модели
**TeraTTS glados2-g2p-vits** с нормализацией текста и расстановкой ударений.

> **Оригинал модели:** [Tera2Space/TeraTTS на GitHub](https://github.com/Tera2Space/TeraTTS) ·
> модель и словарь на Hugging Face: [TeraTTS/glados2-g2p-vits](https://huggingface.co/TeraTTS/glados2-g2p-vits).
> Модель в этом репозитории **не хранится**: она скачивается с Hugging Face при сборке образа,
> закреплённая версия проверяется по SHA-256.

*Russian GLaDOS voice for Home Assistant (Wyoming protocol). Docker image or Home Assistant add-on, x86-64, CPU only.*

В репозитории есть и второй аддон — [**STT Filter**](#второй-аддон-stt-filter--кто-говорит-и-каким-голосом-отвечать):
он узнаёт говорящего по голосу и отвечает каждому своим голосом. Работает с любыми
Wyoming-голосами, GLaDOS для него не обязательна.

## Зачем отдельный сервер

Модель TeraTTS сделана не под Piper: у неё свой набор фонем (`a0`/`a1`, `rj`, `ch`…) и свой
формат входа, поэтому в официальный аддон Piper её не положить. Здесь сервер свой, и текст
проходит такой путь:

1. **Нормализация** (модули [mitrokun](https://github.com/mitrokun/espeak-ng-data) и alisa-tts):
   единицы (°C, м/с, %), латиница (Spotify → «спотифай»), буква «ё».
2. **Числа и время словами**: 6:45 → «шесть сорок пять».
3. **Ударения в омографах** через [silero-stress](https://github.com/snakers4/silero-stress) плюс
   грамматические поправки: замо́к/за́мок, до́ма/дома́, мука́/му́ка.
4. **Фонемы TeraTTS**: словарь на 2 млн слов. Для омографов берётся вариант с ударением, которое
   выбрал silero (оригинальный токенизатор берёт последний вариант, поэтому «уже» читает как «у́же»).
   Для незнакомых слов работают правила TeraTTS.
5. **Синтез** моделью VITS (onnxruntime, 22 050 Гц, CPU).

## Требования

- **x86-64 (amd64)**, Linux с Docker или Home Assistant OS/Supervised. ARM и Raspberry Pi не поддерживаются.
- Около **2 ГБ** на образ и **~650 МБ** памяти при работе. Видеокарта не нужна.
- Интернет **только при сборке**: pip, Hugging Face, GitHub.

**Скорость.** Модель тяжелее голосов Piper. На настольном 6-ядерном процессоре фраза в 3 секунды
синтезируется за ~0,7 с. На маломощном мини-ПК синтез идёт примерно в реальном времени.
Если Home Assistant стоит на слабом железе, запускайте сервер на отдельной машине (вариант А).

## Вариант А. Docker на отдельной машине

```sh
git clone https://github.com/darklion84/glados-tts.git
cd glados-tts
docker build -t glados-tts:1.1.0 ./glados_tts      # ~3 минуты, скачивает torch и модель
mkdir -p data
echo '{"threads": 4, "length_scale": 1.2, "debug": false}' > data/options.json
docker run -d --name glados-tts --restart unless-stopped \
  -p 10200:10200 -v "$PWD/data:/data" glados-tts:1.1.0
docker logs -f glados-tts                          # ждём строку "INFO:glados:Ready"
```

Или через `docker compose up -d --build`: [`docker-compose.yml`](docker-compose.yml) в корне репозитория.

Подключение в Home Assistant: **Настройки → Устройства и службы → Добавить интеграцию →
Wyoming Protocol**, хост — IP этой машины, порт `10200`. Закрепите IP машины в роутере.

> **Порт 10200 не открывайте в интернет.** У Wyoming нет авторизации, а опубликованные Docker
> порты обходят правила `ufw`. На машине с внешним адресом публикуйте порт только в локальную
> сеть: `-p <IP-в-LAN>:10200:10200`.

## Вариант Б. Аддон Home Assistant

Нужен Home Assistant OS или Supervised на x86-64. Образ собирается прямо на машине с HA, и на
слабом железе сборка займёт до 10–15 минут.

**Как репозиторий аддонов:** **Настройки → Дополнения → Магазин дополнений → ⋮ → Репозитории**,
добавьте `https://github.com/darklion84/glados-tts`, найдите **GLaDOS TTS** и нажмите «Установить».

**Или вручную:** скопируйте папку `glados_tts` в общую папку `addons` (например, через аддон
Samba share), чтобы получилось `addons/glados_tts/config.yaml`. Затем **Магазин дополнений → ⋮ →
Проверить наличие обновлений → Локальные дополнения → GLaDOS TTS → Установить**.

После запуска аддона в журнале должно появиться `INFO:glados:Ready`. Подключите интеграцию
**Wyoming Protocol**:
- хост — имя хоста аддона со страницы аддона: для ручной установки `local-glados-tts`, для
  установки из репозитория `<id-репозитория>-glados-tts`; порт `10200`;
- или IP-адрес Home Assistant и порт `10202`.

## Выбор голоса

- Проверка: **Медиа → Text-to-speech →** GLaDOS TTS, голос `ru_RU-glados-medium`.
- Для ассистента: **Настройки → Голосовые ассистенты →** ассистент → **Text-to-speech** → GLaDOS TTS.
- В автоматизациях: `tts.speak` с сущностью GLaDOS (обычно `tts.glados_tts`).

## Настройки

`data/options.json` для Docker или вкладка «Конфигурация» аддона. После изменения перезапустите сервер.

| Параметр | По умолчанию | Описание |
|---|---|---|
| `threads` | `2` | Потоки процессора, ставьте по числу физических ядер |
| `length_scale` | `1.2` | Темп речи: больше — медленнее (`1.2` — значение TeraTTS по умолчанию) |
| `debug` | `false` | Писать в журнал разбор фраз: нормализованный текст, ударения, источник произношения каждого слова |

## Потоковый режим

С версии 1.1.0 сервер принимает текст потоком (`SynthesizeStart` / `SynthesizeChunk` /
`SynthesizeStop`): Home Assistant начинает озвучку, пока языковая модель ещё пишет ответ, и каждое
законченное предложение синтезируется сразу. Звук и раньше отдавался по предложениям.

## Известные ограничения

- silero иногда ошибается в омографах: «Все уже дома» звучит как «всё уже до́ма».
- Числительные не согласуются по роду: «2 минуты» → «два минуты».
- Первое предложение синтезируется целиком, прежде чем зазвучит: на длинном первом предложении
  пауза перед ответом заметнее, чем у голосов Piper.

## Второй аддон: STT Filter — кто говорит и каким голосом отвечать

Папка [`stt_filter`](stt_filter). Это Wyoming-посредник, который ставится между Home Assistant и
вашими серверами распознавания и озвучки. **От GLaDOS он не зависит**: голосом может быть любой
Wyoming-синтезатор — Piper, GLaDOS из этого репозитория или любой другой, в любом количестве.

Что он делает:

1. **Чистит распознанный текст.** Parakeet на шуме в комнате выдаёт короткие английские
   «пустышки» («Yeah.», «Um stop.»). Ответ без кириллицы не длиннее `max_latin_words` слов
   становится пустым, а «stop» / «стоп» / «хватит» среди слов-паразитов — ровно словом «стоп».
   Русские ответы не меняются.
2. **Узнаёт говорящего.** Пока сервер распознаёт речь, по той же записи считается «отпечаток»
   голоса (модель CAM++ из [3D-Speaker](https://github.com/modelscope/3D-Speaker) через
   [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx), 28 МБ, только процессор). Обучать модель
   под человека не нужно: образец — это несколько его обычных фраз. Людей может быть сколько
   угодно, запрос относится к тому, на кого похож больше всего. Задержки это не добавляет.
3. **Отвечает нужным голосом.** Для Home Assistant это один голос `auto`, а текст уходит в тот
   синтезатор, который назначен узнанному человеку; всем остальным отвечает голос по умолчанию.
   Если нужный синтезатор недоступен, отвечает голос по умолчанию.
4. **Сообщает, кто говорил:** сенсор `sensor.voice_speaker` (имя или `unknown`, в атрибутах —
   сходство с каждым образцом). Его можно читать в шаблоне промпта ассистента.

Звук запросов не сохраняется — только отпечатки (векторы) и распознанный текст, в папке аддона
на вашем Home Assistant.

### Установка

Как репозиторий аддонов или вручную — так же, как GLaDOS TTS в варианте Б, только папка
`stt_filter`. Аддон слушает два порта: `10300` (распознавание) и `10200` (озвучка). В Home
Assistant добавьте **две** интеграции Wyoming Protocol на имя хоста аддона (для ручной установки
`local-stt-filter`): с портом `10300` и с портом `10200`. Затем в ассистенте выберите их как
Speech-to-text и Text-to-speech (голос `auto`).

### Настройки

| Параметр | По умолчанию | Описание |
|---|---|---|
| `upstream_host`, `upstream_port` | `core-whisper`, `10300` | Wyoming-сервер распознавания, перед которым стоит посредник |
| `max_latin_words` | `1` | Ответ без кириллицы не длиннее стольких слов считается «пустышкой» |
| `voices` | Piper | Список синтезаторов: `name`, `host`, `port`. Любые Wyoming-голоса |
| `default_voice` | `piper` | Кто отвечает неузнанным и на объявления |
| `speaker_voices` | пусто | Кому какой голос: `speaker` (имя образца) → `voice` (имя из `voices`) |
| `speaker_threshold` | `0.57` | Минимальное сходство с образцом, чтобы человека узнать |
| `speaker_margin` | `0.05` | На сколько самый похожий должен опережать следующего |

Пример: всем отвечает Piper, а одному человеку — GLaDOS на другой машине.

```yaml
default_voice: piper
voices:
  - name: piper
    host: core-piper
    port: 10200
  - name: glados
    host: 192.168.1.50
    port: 10200
speaker_voices:
  - speaker: owner
    voice: glados
```

### Как записать голос

1. Человек говорит колонке 5–10 обычных фраз длиннее двух секунд, лучше из разных мест.
2. Откройте общую папку `addon_configs` (аддон Samba share) и запустите
   [`stt_filter/tools/voiceprints.py`](stt_filter/tools/voiceprints.py) (нужен только Python):

```sh
python voiceprints.py --dir /путь/к/addon_configs/local_stt_filter list            # последние запросы
python voiceprints.py --dir … enroll owner --since 21:40 --until 21:45             # показать, что попадёт
python voiceprints.py --dir … enroll owner --since 21:40 --until 21:45 --yes       # записать образец
python voiceprints.py --dir … report                                               # сходство «свой/чужой»
```

Аддон подхватывает образцы сам, перезапуск не нужен. Порог подбирайте по `report`: он должен
лежать между сходством своих фраз и самыми похожими чужими.

**Записывайте всех, кто часто говорит с колонкой,** даже если отдельный голос им не нужен.
Одного порога мало: в проверке фразы второго человека доходили до 0,48 при пороге 0,5. Когда
записаны оба, запрос относится к тому, на кого похож больше, и те же фразы уверенно уходят
«своему» образцу (0,66–0,75 против 0,42–0,48).

### Ограничения

- **Короткие фразы узнаются плохо.** На открытых записях 30 русскоязычных дикторов с имитацией
  расстояния: при 1 секунде речи ошибок около 12 %, при 2 секундах — около 3 %, при 3 — около 1 %.
  Неузнанному отвечает голос по умолчанию.
- **Home Assistant хранит озвученные фразы по тексту** и не знает, что голос зависит от человека.
  Поэтому при смене голоса аддон очищает это хранилище (`tts.clear_cache`) — для всех синтезаторов.
- **Объявления** (таймер, автоматизации) звучат голосом по умолчанию. Исключение: объявление в
  первые 45 секунд после запроса, ответ на который Home Assistant взял из хранилища, прозвучит
  голосом спросившего.
- Правила очистки текста написаны под Parakeet и русский язык.

## Как это проверялось

- Docker-образ собран с нуля из этого репозитория на Ubuntu 22.04 (x86-64). Синтез по Wyoming и
  через Home Assistant работает.
- Тот же сервер работал как локальный аддон Home Assistant OS, но в предварительной сборке, где
  зависимости были вшиты, а не скачивались. **Сборка аддона из этого репозитория** (оба способа
  варианта Б) **пока не проверялась.** Запуск через `docker compose` тоже не проверялся.
- Юнит-тесты разбора текста: `python -m unittest discover -s tests` (без модели и сети).
- **STT Filter**: образ собран на Ubuntu 22.04 (x86-64); аддон работает на Home Assistant OS,
  установленный вручную из папки, с Parakeet, Piper и GLaDOS, на двух записанных голосах.
  Установка из репозитория аддонов и сборка под aarch64 **не проверялись**. Его тесты
  (`tests/test_stt_filter.py`) требуют `pip install wyoming numpy sherpa-onnx`, без них пропускаются.

## Структура

```
glados_tts/
├── Dockerfile, config.yaml, run.sh, requirements.txt
├── app/glados_server.py        Wyoming-сервер и обработка текста
├── app/glados_g2p.py           фонемы TeraTTS: словарь (SQLite) + правила
├── tools/fetch.py              скачивание модели и нормализаторов при сборке (SHA-256)
├── tools/build_dict.py         dictionary.txt → SQLite (словарь не держится в памяти)
└── third_party/alisa_tts/      модули нормализации из alisa-tts (см. README там)
stt_filter/
├── Dockerfile, config.yaml, run.sh
├── main.py                     запуск: распознавание (10300) и озвучка (10200) в одном процессе
├── stt_filter.py               посредник распознавания и очистка текста
├── speaker.py                  отпечатки голоса и выбор говорящего
├── tts_router.py               выбор синтезатора по говорящему
├── fetch_model.py              скачивание модели отпечатков при сборке (SHA-256)
└── tools/voiceprints.py        запись образцов голосов (запускается на компьютере)
repository.yaml                 описание репозитория аддонов Home Assistant
docker-compose.yml
tests/test_g2p.py, tests/test_stt_filter.py
```
