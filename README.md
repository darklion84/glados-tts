# GLaDOS TTS для Home Assistant

Русский голос **GLaDOS** для Home Assistant: Wyoming-сервер на основе модели
**TeraTTS glados2-g2p-vits** с нормализацией текста и расстановкой ударений.

> **Оригинал модели:** [Tera2Space/TeraTTS на GitHub](https://github.com/Tera2Space/TeraTTS) ·
> модель и словарь на Hugging Face: [TeraTTS/glados2-g2p-vits](https://huggingface.co/TeraTTS/glados2-g2p-vits).
> Модель в этом репозитории **не хранится**: она скачивается с Hugging Face при сборке образа,
> закреплённая версия проверяется по SHA-256.

*Russian GLaDOS voice for Home Assistant (Wyoming protocol). Docker image or Home Assistant add-on, x86-64, CPU only.*

## Зачем отдельный сервер

Модель TeraTTS сделана не под Piper: у неё свой набор фонем (`a0`/`a1`, `rj`, `ch`…) и свой
формат входа, поэтому в официальный аддон Piper её не положить. Здесь сервер свой, и текст
проходит такой путь:

1. **Нормализация** (модули [mitrokun](https://github.com/mitrokun/espeak-ng-data) и alisa-tts):
   единицы (°C, м/с, %), латиница (Spotify → «спотифай»), буква «ё».
2. **Числа и время словами**: 6:45 → «шесть сорок пять».
3. **Ударения в омографах** через [silero-stress](https://github.com/snakers4/silero-stress) плюс
   грамматические поправки: замо́к/за́мок, до́ма/дома́, мука́/му́ка.
4. **Фонемы TeraTTS**: словарь на 2 млн слов. Для омографов берётся вариант с ударением, которое
   выбрал silero (оригинальный токенизатор берёт последний вариант, поэтому «уже» читает как «у́же»).
   Для незнакомых слов работают правила TeraTTS.
5. **Синтез** моделью VITS (onnxruntime, 22 050 Гц, CPU).

## Требования

- **x86-64 (amd64)**, Linux с Docker или Home Assistant OS/Supervised. ARM и Raspberry Pi не поддерживаются.
- Около **2 ГБ** на образ и **~650 МБ** памяти при работе. Видеокарта не нужна.
- Интернет **только при сборке**: pip, Hugging Face, GitHub.

**Скорость.** Модель тяжелее голосов Piper. На настольном 6-ядерном процессоре фраза в 3 секунды
синтезируется за ~0,7 с. На маломощном мини-ПК синтез идёт примерно в реальном времени.
Если Home Assistant стоит на слабом железе, запускайте сервер на отдельной машине (вариант А).

## Вариант А. Docker на отдельной машине

```sh
git clone https://github.com/darklion84/glados-tts.git
cd glados-tts
docker build -t glados-tts:1.0.0 ./glados_tts      # ~3 минуты, скачивает torch и модель
mkdir -p data
echo '{"threads": 4, "length_scale": 1.2, "debug": false}' > data/options.json
docker run -d --name glados-tts --restart unless-stopped \
  -p 10200:10200 -v "$PWD/data:/data" glados-tts:1.0.0
docker logs -f glados-tts                          # ждём строку "INFO:glados:Ready"
```

Или через `docker compose up -d --build`: [`docker-compose.yml`](docker-compose.yml) в корне репозитория.

Подключение в Home Assistant: **Настройки → Устройства и службы → Добавить интеграцию →
Wyoming Protocol**, хост — IP этой машины, порт `10200`. Закрепите IP машины в роутере.

> **Порт 10200 не открывайте в интернет.** У Wyoming нет авторизации, а опубликованные Docker
> порты обходят правила `ufw`. На машине с внешним адресом публикуйте порт только в локальную
> сеть: `-p <IP-в-LAN>:10200:10200`.

## Вариант Б. Аддон Home Assistant

Нужен Home Assistant OS или Supervised на x86-64. Образ собирается прямо на машине с HA, и на
слабом железе сборка займёт до 10–15 минут.

**Как репозиторий аддонов:** **Настройки → Дополнения → Магазин дополнений → ⋮ → Репозитории**,
добавьте `https://github.com/darklion84/glados-tts`, найдите **GLaDOS TTS** и нажмите «Установить».

**Или вручную:** скопируйте папку `glados_tts` в общую папку `addons` (например, через аддон
Samba share), чтобы получилось `addons/glados_tts/config.yaml`. Затем **Магазин дополнений → ⋮ →
Проверить наличие обновлений → Локальные дополнения → GLaDOS TTS → Установить**.

После запуска аддона в журнале должно появиться `INFO:glados:Ready`. Подключите интеграцию
**Wyoming Protocol**:
- хост — имя хоста аддона со страницы аддона: для ручной установки `local-glados-tts`, для
  установки из репозитория `<id-репозитория>-glados-tts`; порт `10200`;
- или IP-адрес Home Assistant и порт `10202`.

## Выбор голоса

- Проверка: **Медиа → Text-to-speech →** GLaDOS TTS, голос `ru_RU-glados-medium`.
- Для ассистента: **Настройки → Голосовые ассистенты →** ассистент → **Text-to-speech** → GLaDOS TTS.
- В автоматизациях: `tts.speak` с сущностью GLaDOS (обычно `tts.glados_tts`).

## Настройки

`data/options.json` для Docker или вкладка «Конфигурация» аддона. После изменения перезапустите сервер.

| Параметр | По умолчанию | Описание |
|---|---|---|
| `threads` | `2` | Потоки процессора, ставьте по числу физических ядер |
| `length_scale` | `1.2` | Темп речи: больше — медленнее (`1.2` — значение TeraTTS по умолчанию) |
| `debug` | `false` | Писать в журнал разбор фраз: нормализованный текст, ударения, источник произношения каждого слова |

## Известные ограничения

- silero иногда ошибается в омографах: «Все уже дома» звучит как «всё уже до́ма».
- Числительные не согласуются по роду: «2 минуты» → «два минуты».
- Звук отдаётся целиком после синтеза всей фразы, потокового режима нет.

## Как это проверялось

- Docker-образ собран с нуля из этого репозитория на Ubuntu 22.04 (x86-64). Синтез по Wyoming и
  через Home Assistant работает.
- Тот же сервер работал как локальный аддон Home Assistant OS, но в предварительной сборке, где
  зависимости были вшиты, а не скачивались. **Сборка аддона из этого репозитория** (оба способа
  варианта Б) **пока не проверялась.** Запуск через `docker compose` тоже не проверялся.
- Юнит-тесты разбора текста: `python -m unittest discover -s tests` (без модели и сети).

## Структура

```
glados_tts/
├── Dockerfile, config.yaml, run.sh, requirements.txt
├── app/glados_server.py        Wyoming-сервер и обработка текста
├── app/glados_g2p.py           фонемы TeraTTS: словарь (SQLite) + правила
├── tools/fetch.py              скачивание модели и нормализаторов при сборке (SHA-256)
├── tools/build_dict.py         dictionary.txt → SQLite (словарь не держится в памяти)
└── third_party/alisa_tts/      модули нормализации из alisa-tts (см. README там)
repository.yaml                 описание репозитория аддонов Home Assistant
docker-compose.yml
tests/test_g2p.py
```
